# Pylint: History, Usage & VSCode Configuration

---

## History & Creation

Pylint is a static code analysis tool for Python, developed by **Sylvain Thénault**. Its name follows the common Python convention of a `py` prefix, combined with a nod to the classic C programming `lint` program. It follows the style recommended by **PEP 8**.

Pylint was born in **2003 at Logilab**, which funded Sylvain Thénault to lead its development. It checks for errors in Python code, enforces a coding standard, and looks for bad code smells — similar to but different from tools like PyChecker, which explicitly did not bother with coding style.

A key design decision is that Pylint doesn't trust your type annotations — instead it infers the actual values of nodes using its internal code representation (**astroid**). For example, if your code has `import logging as argparse`, Pylint can determine that `argparse.error(...)` is actually a logging call. This makes Pylint slower, but lets it find more issues even in code that isn't fully typed.

## How to Use Pylint

### Installation

```bash
pip install pylint
```

### Running Pylint

```bash
# Lint a single file
pylint my_script.py

# Lint an entire package
pylint my_package/
```

### Common CLI Flags

```bash
pylint --disable=C0114,C0115       # Disable specific warnings
pylint --max-line-length=120 app.py
pylint --rcfile=.pylintrc app.py   # Use a custom config file
```

### Generate a Base Config File

```bash
pylint --generate-rcfile > .pylintrc
```

You can modify `.pylintrc` to customize which errors or conventions matter to you. Pylint is highly configurable, and you can even write small plugins to add custom features.

### Inline Suppression in Code

```python
x = 1  # pylint: disable=invalid-name
```

## VSCode Extension Configuration

Install the **official Microsoft Pylint extension** (`ms-python.pylint`) from the Extensions panel in VS Code.

The extension automatically activates when you open Python files, `.pylintrc` configuration files, or any workspace containing Python files.

---

### Key `settings.json` Options

#### 1. Choose Which Pylint Version to Use

```json
// Use the version bundled with the extension (default)
"pylint.importStrategy": "useBundled"

// Use the version installed in your virtual environment
"pylint.importStrategy": "fromEnvironment"
```

#### 2. Pass Custom Arguments

Each argument must be a separate string in the array:

```json
"pylint.args": [
  "--disable=C0114",
  "--disable=C0115",
  "--max-line-length=120",
  "--rcfile=.pylintrc"
]
```

#### 3. Enable Live Linting as You Type

```json
"pylint.lintOnChange": true
```

> Note: Provides immediate feedback but may impact performance.

#### 4. Map Severity Levels

```json
"pylint.severity": {
  "convention": "Information",
  "error": "Error",
  "fatal": "Error",
  "refactor": "Hint",
  "warning": "Warning",
  "W0611": "Error"
}
```

#### 5. Set Working Directory (useful for monorepos)

```json
"pylint.cwd": "${fileDirname}"
```

#### 6. Ignore Certain Files or Folders

```json
"pylint.ignorePatterns": ["**/tests/**", "**/__pycache__/**"]
```

#### 7. Use a Custom Pylint Path (e.g., inside a conda environment)

```json
"pylint.path": ["conda", "run", "-n", "lint_env", "python", "-m", "pylint"]
```

---

### Full Example `settings.json`

```json
{
  "pylint.importStrategy": "fromEnvironment",
  "pylint.lintOnChange": false,
  "pylint.args": [
    "--disable=C0114,C0115,C0116",
    "--max-line-length=120"
  ],
  "pylint.severity": {
    "convention": "Information",
    "refactor": "Hint",
    "warning": "Warning",
    "error": "Error"
  }
}
```

---

### A Note on `.pylintrc`

While the VS Code extension doesn't directly parse `.pylintrc` files, Pylint itself will discover and use them according to its standard configuration search order. Placing a `.pylintrc` in your project root is a great way to manage per-project rules and keep settings consistent across your team.
